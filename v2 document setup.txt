BACKPACK AIR — DOCUMENT SYSTEM V2
CRITICAL ARCHITECTURE + EDITOR REDESIGN

Do NOT start by changing colors or cosmetic styling.

First fix the document architecture and persistence, then implement the new creation flow and editor.

Backpack Air remains an OFFLINE DIGITAL SCHOOLBAG.

==================================================
1. CRITICAL: UPDATES MUST NEVER DELETE USER DATA
==================================================

CURRENT BUG:

When the application is updated, users lose:

- notebooks
- pages
- handwriting
- sheets
- quick notes
- folders
- bookmarks
- PDF annotations
- preferences
- other locally-created content

THIS MUST BE FIXED BEFORE ANYTHING ELSE.

User-created data must be stored separately from application code/version updates.

Application updates must NOT reset the user's database.

DO NOT use:

- hardcoded initial data that overwrites existing data
- localStorage initialization that resets existing values
- version upgrades that clear storage
- destructive database migrations

Create a persistent local data layer with schema versioning/migrations.

On application startup:

1. Open existing user database.
2. Detect database version.
3. Run non-destructive migration if necessary.
4. Preserve every existing document.
5. Add new fields only when required.
6. Never delete user content automatically.

The following are USER DATA and must survive every application update:

- notebooks
- notebook pages
- handwritten strokes
- notebook covers
- paper styles
- sheets
- whiteboards
- quick notes
- folders
- folder colors
- folder icons
- PDF bookmarks
- PDF annotations
- last-read PDF page
- homework diary entries
- preferences
- student name
- selected school/class/section

If a migration cannot safely preserve something, DO NOT silently delete it.

==================================================
4. REAL PAGE SIZE
==================================================

Notebook pages must behave like real paper.

Default page:

A4

Ratio:

210 × 297 mm

The page must maintain its A4 aspect ratio regardless of screen size.

On a tablet:

- page fits vertically/horizontally depending on available space
- writing area remains proportional
- no stretched pages
- no giant canvas overflowing outside the viewport

The same document should look like the same physical page on different screen sizes.

Implement page rendering around a document coordinate system rather than drawing directly based on viewport pixels.

This is critical for handwriting persistence.
